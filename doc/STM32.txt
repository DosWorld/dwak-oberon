        Oberon-07/16 programming language compiler for
            STM32 Cortex-M3 microcontrollers.

------------------------------------------------------------------------------
        Command line options

  Input - text module files with the ".ob07" extension, ANSI or UTF-8
encoding with a BOM signature.
  Output - a hex firmware file.
  Parameters:
  1) name of the main module
  2) "stm32cm3"
  3) optional switch parameters
      -out <file_name> name of the resulting file; by default, it
          matches the name of the main module, but with the ".hex" extension
      -ram <size> RAM size in kilobytes (4 - 65536), default 4
      -rom <size> ROM size in kilobytes (16 - 65536), default 16
      -tab <width> tab width (used to compute positions in the
          source text), default - 4
      -nochk <"ptibcwra"> disable runtime checks
      -lower allow keywords and built-in identifiers in
          lower case (default)
      -upper upper case only for keywords and built-in
          identifiers
      -def <name> define a conditional compilation symbol
      -uses print the list of imported modules

      the -nochk parameter is given as a string of characters:
      "p" - pointers
      "t" - types
      "i" - indexes
      "b" - implicit conversion of INTEGER to BYTE
      "c" - range of the argument of the CHR function
      "w" - range of the argument of the WCHR function
      "r" - equivalent to "bcw"
      "a" - all checks

      The order of the characters can be arbitrary. The presence of a
      particular character in the string disables the corresponding check.

      For example: -nochk it - disable index checking and type guard.
      -nochk a - disable all disableable checks.

  For example:

  Compiler.exe "C:\example.ob07" stm32cm3 -ram 32 -rom 256 -nochk pti
  Compiler.exe "C:\example.ob07" stm32cm3 -out "C:\Ex1.hex" -ram 8 -rom 32

  If the compilation succeeds, the compiler returns exit code 0, otherwise 1.

------------------------------------------------------------------------------
        Differences from the original

 1.     The SYSTEM pseudo-module has been extended
 2.     The "_" character is allowed in identifiers
 3.     The CASE statement has been improved (constant expressions have been
        added to variant labels and an optional ELSE branch has been added)
 4.     The set of standard procedures has been extended
 5.     Type guard/type check semantics has been refined for a nil pointer
 6.     Single-line comments have been added (they start with the pair "//")
 7.     Inheritance from a pointer type is allowed
 8.     "Strings" can also be enclosed in single quotes: 'string'
 9.     The WCHAR type has been added
10.     Concatenation of string and character constants has been added
11.     Code procedures have been added
12.     Modules can be imported with a path and file name specified
13.     Special syntax for conditional compilation has been added (see CC.txt)
14.     The procedure name at the end of the declaration (after END) is optional
15.     Lower case is allowed for keywords

------------------------------------------------------------------------------
        Implementation notes

1.      Basic types

          Type              Value range                          Size, bytes

        INTEGER       -2147483648 .. 2147483647                         4
        REAL          1.17E-38 .. 3.40E+38                              4
        CHAR          ASCII character (0X .. 0FFX)                      1
        BOOLEAN       FALSE, TRUE                                       1
        SET           a set of integers {0 .. 31}                       4
        BYTE          0 .. 255                                          1
        WCHAR         unicode character (0X .. 0FFFFX)                  2

2.      Maximum identifier length - 255 characters
3.      Maximum length of string constants - 511 characters (UTF-8)
4.      Maximum number of dimensions of open arrays - 5
5.      The NEW procedure fills the allocated memory block with zeros
6.      Local variables are initialized to zeros
7.      Unlike many Oberon implementations, a garbage collector and dynamic
        modularity are absent
8.      The BYTE type is always converted to INTEGER in expressions
9.      Overflow of expression values is not checked

------------------------------------------------------------------------------
        SYSTEM pseudo-module

  The SYSTEM pseudo-module contains low-level and unsafe procedures; errors in
the use of SYSTEM pseudo-module procedures can lead to corruption of runtime
data and abnormal termination of the program.

        PROCEDURE ADR(v: any type): INTEGER
                v - a variable or a procedure;
                returns the address of v

        PROCEDURE SADR(x: string constant (CHAR UTF-8)): INTEGER
                returns the address of x

        PROCEDURE WSADR(x: string constant (WCHAR)): INTEGER
                returns the address of x

        PROCEDURE VAL(T; v: any type): T
                v - a variable;
                interprets v as a variable of type T

        PROCEDURE SIZE(T): INTEGER
                returns the size of type T

        PROCEDURE TYPEID(T): INTEGER
                T - a record type or a pointer type,
                returns the type number in the table of record types

        PROCEDURE INF(): REAL
                returns the special real value "infinity"

        PROCEDURE MOVE(Source, Dest, n: INTEGER)
                Copies n bytes of memory from Source to Dest,
                the Source and Dest areas must not overlap

        PROCEDURE GET(a: INTEGER;
                VAR v: any basic type, PROCEDURE, POINTER)
                v := Memory[a]

        PROCEDURE GET8(a: INTEGER;
                       VAR x: INTEGER, SET, BYTE, CHAR, WCHAR, SYSTEM.CARD32)
                Equivalent to
                SYSTEM.MOVE(a, SYSTEM.ADR(x), 1)

        PROCEDURE GET16(a: INTEGER;
                        VAR x: INTEGER, SET, WCHAR, SYSTEM.CARD32)
                Equivalent to
                SYSTEM.MOVE(a, SYSTEM.ADR(x), 2)

        PROCEDURE GET32(a: INTEGER; VAR x: INTEGER, SET, SYSTEM.CARD32)
                Equivalent to
                SYSTEM.MOVE(a, SYSTEM.ADR(x), 4)

        PROCEDURE PUT(a: INTEGER; x: any basic type, PROCEDURE, POINTER)
                Memory[a] := x;
                If x: BYTE or x: WCHAR, then the value of x is extended
                to 32 bits; to write bytes use SYSTEM.PUT8,
                for WCHAR -- SYSTEM.PUT16

        PROCEDURE PUT8(a: INTEGER;
                       x: INTEGER, SET, BYTE, CHAR, WCHAR, SYSTEM.CARD32)
                Memory[a] := the low 8 bits of (x)

        PROCEDURE PUT16(a: INTEGER;
                        x: INTEGER, SET, BYTE, CHAR, WCHAR, SYSTEM.CARD32)
                Memory[a] := the low 16 bits of (x)

        PROCEDURE PUT32(a: INTEGER;
                        x: INTEGER, SET, BYTE, CHAR, WCHAR, SYSTEM.CARD32)
                Memory[a] := the low 32 bits of (x)

        PROCEDURE CODE(hword1, hword2,... : INTEGER)
                Insertion of machine code,
                hword1, hword2 ... - constants in the range 0..65535,
                for example:
                SYSTEM.CODE(0BF30H) (* wfi *)

  Also, the type CARD32 (4 bytes) is defined in the SYSTEM module. No explicit
operations are allowed for the CARD32 type, except for assignment.

  SYSTEM pseudo-module functions cannot be used in constant expressions.

------------------------------------------------------------------------------
        CASE statement

  Syntax of the CASE statement:

        CaseStatement =
                CASE Expression OF Case {"|" Case}
                        [ELSE StatementSequence] END.
        Case = [CaseLabelList ":" StatementSequence].
        CaseLabelList = CaseLabels {"," CaseLabels}.
        CaseLabels = ConstExpression [".." ConstExpression].

  For example:

        CASE x OF
        |-1:    DoSomething1
        | 1:    DoSomething2
        | 0:    DoSomething3
        ELSE
                DoSomething4
        END

  Constant expressions can be used in variant labels, and the ELSE branch is
optional. If the value of x matches no variant and the ELSE branch is absent,
the program is terminated with a runtime error.

------------------------------------------------------------------------------
        WCHAR type

  The WCHAR type has been added to the language for convenient unicode support.
For the WCHAR and ARRAY OF WCHAR types, all the same operations are allowed as
for the CHAR and ARRAY OF CHAR types, except for the built-in procedure CHR,
which returns only the CHAR type. To obtain a value of type WCHAR, the WCHR
procedure should be used instead of CHR. For correct operation with the type,
the source code must be saved in UTF-8 encoding with a BOM.

------------------------------------------------------------------------------
        Concatenation of string and character constants

  Concatenation ("+") of constant strings and characters of type CHAR is allowed:

  str = CHR(39) + "string" + CHR(39); (* str = "'string'" *)

  newline = 0DX + 0AX;

------------------------------------------------------------------------------
        Type check and type guard of a nil pointer

  The original language report does not define the behavior of a program when
the type guard p(T) and the type test p IS T are executed with p = NIL. In many
Oberon implementations, performing such an operation results in a runtime
error. In this implementation, a type guard of a nil pointer does not cause an
error, and the type test yields FALSE. In a number of cases this allows the
frequency of type guard usage to be reduced significantly.

------------------------------------------------------------------------------
        Additional standard procedures


        COPY (x: ARRAY OF CHAR/WCHAR; VAR v: ARRAY OF CHAR/WCHAR);
                v := x;
                If LEN(v) < LEN(x), then the string x will be copied
                incompletely

        LSR (x, n: INTEGER): INTEGER
                Logical shift of x right by n bits.

        MIN (a, b: INTEGER): INTEGER
                Minimum of two values.

        MAX (a, b: INTEGER): INTEGER
                Maximum of two values.

        BITS (x: INTEGER): SET
                Interprets x as a value of type SET.
                Performed at compile time.

        LENGTH (s: ARRAY OF CHAR/WCHAR): INTEGER
                Length of the 0X-terminated string s, excluding the 0X
                character. If the 0X character is absent, the function returns
                the length of the array s. s cannot be a constant.

        WCHR (n: INTEGER): WCHAR
                Type conversion, similar to CHR(n: INTEGER): CHAR

------------------------------------------------------------------------------
        Floating point

  The compiler is intended for devices with a Cortex-M3 core and, possibly,
after minor rework, also for Cortex-M0. Such microcontrollers have no built-in
floating point support, so operations with single-precision real numbers are
emulated (module lib/STM32CM3/FPU.ob07). The compiler substitutes procedure
calls at the site of real number operations.

  The possibility of reworking the compiler in the future for devices with
built-in real number support is retained.

------------------------------------------------------------------------------
        Use of general purpose registers R0 - R12

        R0 - R3:  register stack (intermediate values of expressions),
                  volatile registers (do not need to be saved)

        R4 - R7:  not used by the compiler, may be used in code procedures,
                  non-volatile (must be saved before use and restored
                  afterwards)

        R8 - R12: reserved for possible special purpose in the
                  future

------------------------------------------------------------------------------
        Procedure calls and stack frame

  The calling rules are similar to the cdecl convention (x86):
  - parameters are passed on the stack from right to left
  - the result, if any, is passed in register R0
  - the calling procedure cleans up the stack

  Stack state during execution of a procedure:

  lower addresses <- |var3|var2|var1|LR|arg1|arg2|arg3| -> higher addresses

  LR   - saved LR register (return address)
  argX - parameters in declaration order (left to right)
  varX - local variables in order of use in the procedure

  The size of each stack element (except local variables of structural
  types) is 1 machine word (4 bytes). Structural variables (arrays and
  records) occupy stack space according to their size (taking alignment
  into account).

  The placement of local variables depends on their sizes and order of use,
  and in the general case is undefined. If a variable is not used explicitly,
  the compiler does not allocate stack space for it.

------------------------------------------------------------------------------
        Hidden procedure parameters

  Some procedures may have hidden parameters; they are absent from the list of
formal parameters but are taken into account by the compiler when translating
calls. This is possible in the following cases:

1.      The procedure has a formal parameter that is an open array:
                PROCEDURE Proc (x: ARRAY OF ARRAY OF REAL);
        The call is translated as follows:
                Proc(LEN(x), LEN(x[0]), SYSTEM.ADR(x))
2.      The procedure has a formal variable parameter of type RECORD:
                PROCEDURE Proc (VAR x: Rec);
        The call is translated as follows:
                Proc(SYSTEM.TYPEID(Rec), SYSTEM.ADR(x))

------------------------------------------------------------------------------
        Code procedures

  The compiler supports procedures written in machine code.
  Syntax:

  PROCEDURE "[code]" name [ (parameters): ResultType ]
      MachineInstruction, MachineInstruction,... MachineInstruction;

  A ";" after the header and END "name" at the end of the procedure are omitted.
  MachineInstruction - an integer constant [0..65535] (including a constant
  expression).

  Examples:

  PROCEDURE [code] WFI
      0BF30H; (* wfi *)

  (* sum of squares (a*a + b*b) -> r0 *)
  PROCEDURE [code] SqrSum (a, b: INTEGER): INTEGER
      0B430H, (* push {r4, r5}    *) (* save all used registers,
                                        except r0, r1, r2, r3 *)
      09C02H, (* ldr r4, [sp, 8]  *) (* r4 <- a *)
      09D03H, (* ldr r5, [sp, 12] *) (* r5 <- b *)
      04364H, (* muls r4, r4      *) (* r4 := r4 * r4 *)
      0436DH, (* muls r5, r5      *) (* r5 := r5 * r5 *)
      01960H, (* adds r0, r4, r5  *) (* r0 := r4 + r5; result in r0 *)
      0BC30H; (* pop {r4, r5}     *) (* restore registers *)

  The compiler automatically appends a return instruction (bx LR) to such a
procedure. The way parameters and the result are passed does not change. The
LR register is not saved on entry to the procedure.

  To use code procedures, it is necessary to import the SYSTEM
pseudo-module.

------------------------------------------------------------------------------
        Interrupt handling

  When an interrupt occurs, the handler will be called (if it is declared).
Handler declaration:

    PROCEDURE handler_name [iv]; (* procedure without parameters *)

iv - an integer constant (constant expression), the number of the interrupt
vector in the vector table, iv >= 2:

     0       initial value of SP
     1       reset
    ...
    15       SysTick
    ...
    59       TIM6
    60       TIM7
    ...

for example:

    (* TIM6 interrupt handler *)
    PROCEDURE tim6 [59];
    BEGIN
        (* handling code *)
    END tim6;

  Also, a common handler can be declared (iv = 0), which will be called if no
individual handler is assigned. The common handler receives a parameter - the
interrupt vector number. From the value of this parameter, the handler must
determine the interrupt source and perform the corresponding actions:

    PROCEDURE handler (iv: INTEGER) [0];
    BEGIN
        IF iv = 59 THEN
            (* TIM6 *)
        ELSIF iv = 60 THEN
            (* TIM7 *)
        ELSIF ....
        ....
        END
    END handler;

------------------------------------------------------------------------------
        Error handling

  If an error occurs during execution of the program, a user handler will be
called (if it is declared). Before the handler is called, interrupts will be
disabled.

Declaration of the error handler:

    PROCEDURE trap (modNum, modName, err, line: INTEGER) [1];
    BEGIN
    END trap;

    where,
        modNum  - module number (in the compilation report:
                  compiling (modNum) "modName" )
        modName - address of the module name
        err     - error code
        line    - line number

Error codes:

 1       ASSERT(x), when x = FALSE
 2       dereferencing a nil pointer
 3       integer division by a non-positive number
 4       call of a procedure through a procedure variable with a nil value
 5       type guard error
 6       array bounds violation
 7       unhandled expression value in a CASE statement
 8       array copy error v := x, when LEN(v) < LEN(x)
 9       CHR(x), when (x < 0) OR (x > 255)
10       WCHR(x), when (x < 0) OR (x > 65535)
11       implicit conversion of x:INTEGER to v:BYTE, when (x < 0) OR (x > 255)

After return from the handler, the program will be restarted.
