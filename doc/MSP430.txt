        Oberon-07/16 programming language compiler for
            MSP430x{1,2}xx microcontrollers.
------------------------------------------------------------------------------

        Command line options

  Input - text files of modules with the extension ".ob07", ANSI or
UTF-8 encoding with a BOM signature.
  Output - a firmware hex file.
  Options:
  1) name of the main module
  2) "msp430"
  3) optional switches
      -out <file_name> name of the resulting file; by default it
          matches the name of the main module, but with the ".hex" extension
      -ram <size> RAM size in bytes (128 - 2048) default 128
      -rom <size> ROM size in bytes (2048 - 24576) default 2048
      -tab <width> tab size (used to compute positions in the
          source text), default - 4
      -nochk <"ptibcwra"> disable run-time checks
      -lower allow keywords and built-in identifiers in
          lower case (default)
      -upper upper case only for keywords and built-in
          identifiers
      -def <name> define a conditional compilation symbol
      -uses output the list of imported modules

      the -nochk option is given as a string of characters:
      "p" - pointers
      "t" - types
      "i" - indexes
      "b" - implicit conversion of INTEGER to BYTE
      "c" - range of the CHR function argument
      "s" - stack overflow
      "a" - all checks

      The order of the characters can be arbitrary. The presence of a
      particular character in the string disables the corresponding check.

      For example: -nochk it - disable index checking and the type guard.
      -nochk a - disable all checks that can be disabled.

  For example:

  Compiler.exe "C:\example.ob07" msp430 -ram 128 -rom 4096 -nochk pti
  Compiler.exe "C:\example.ob07" msp430 -out "C:\Ex1.hex" -ram 512 -rom 16384

  If compilation is successful, the compiler returns exit code 0, otherwise 1.

------------------------------------------------------------------------------
        Differences from the original

 1.     The SYSTEM pseudo-module is extended
 2.     The character "_" is allowed in identifiers
 3.     The CASE statement is improved (constant expressions in
        case labels and an optional ELSE branch are added)
 4.     The set of standard procedures is extended
 5.     The semantics of the type guard/type test is refined for a null pointer
 6.     One-line comments are added (they start with the pair of characters "//")
 7.     Inheritance from a pointer type is allowed
 8.     "Strings" can also be enclosed in single quotes: 'string'
 9.     The operation of concatenation of string and character constants is added
10.     Code procedures are added
11.     Real arithmetic is not implemented
12.     Modules can be imported with a path and file name
13.     Special syntax for conditional compilation is added (see CC.txt)
14.     The procedure name at the end of the declaration (after END) is optional
15.     Lower case is allowed for keywords

------------------------------------------------------------------------------
        Implementation details

1.      Basic types

          Type             Range of values                 Size, bytes

        INTEGER       -32768 .. 32767                          2
        CHAR          ASCII character (0X .. 0FFX)             1
        BOOLEAN       FALSE, TRUE                              1
        SET           set of integers {0 .. 15}                2
        BYTE          0 .. 255                                 1

2.      Maximum length of identifiers - 255 characters
3.      Maximum length of string constants - 511 characters (UTF-8)
4.      Maximum number of dimensions of open arrays - 5
5.      The NEW procedure fills the allocated memory block with zeros
6.      Local variables are initialized with zeros
7.      Unlike many Oberon implementations, there is no garbage collector and
        no dynamic module loading
8.      The BYTE type in expressions is always converted to INTEGER
9.      Overflow of expression values is not checked

------------------------------------------------------------------------------
        The SYSTEM pseudo-module

  The SYSTEM pseudo-module contains low-level and unsafe procedures;
errors in the use of SYSTEM pseudo-module procedures can lead to
corruption of run-time data and abnormal termination of the program.

        PROCEDURE ADR(v: any type): INTEGER
                v - a variable or a procedure;
                returns the address of v

        PROCEDURE SADR(x: string constant): INTEGER
                returns the address of x

        PROCEDURE VAL(T; v: any type): T
                v - a variable;
                interprets v as a variable of type T

        PROCEDURE SIZE(T): INTEGER
                returns the size of type T

        PROCEDURE TYPEID(T): INTEGER
                T - a record type or a pointer type,
                returns the type number in the table of record types

        PROCEDURE MOVE(Source, Dest, n: INTEGER)
                Copies n bytes of memory from Source to Dest,
                the Source and Dest areas must not overlap

        PROCEDURE GET(a: INTEGER;
                VAR v: any basic type, PROCEDURE, POINTER)
                v := Memory[a]

        PROCEDURE GET8(a: INTEGER; VAR x: INTEGER, SET, BYTE, CHAR)
                Equivalent to
                SYSTEM.MOVE(a, SYSTEM.ADR(x), 1)

        PROCEDURE PUT(a: INTEGER; x: any basic type, PROCEDURE, POINTER)
                Memory[a] := x;
                If x is of type BYTE, the value of x is extended to 16 bits,
                use SYSTEM.PUT8 to write bytes

        PROCEDURE PUT8(a: INTEGER; x: INTEGER, SET, BYTE, CHAR)
                Memory[a] := the low 8 bits of (x)

        PROCEDURE CODE(word1, word2,... : INTEGER)
                Insertion of machine code,
                word1, word2 ... - integer constants (constant
                expressions) - machine words, for example:
                SYSTEM.CODE(0D032H, 0010H) (* BIS #16, SR; CPUOFF *)


  The functions of the SYSTEM pseudo-module cannot be used in constant expressions.

------------------------------------------------------------------------------
        The CASE statement

  Syntax of the CASE statement:

        CaseStatement =
                CASE Expression OF Case {"|" Case}
                        [ELSE StatementSequence] END.
        Case = [CaseLabelList ":" StatementSequence].
        CaseLabelList = CaseLabels {"," CaseLabels}.
        CaseLabels = ConstExpression [".." ConstExpression].

  For example:

        CASE x OF
        |-1:    DoSomething1
        | 1:    DoSomething2
        | 0:    DoSomething3
        ELSE
                DoSomething4
        END

  Constant expressions can be used in case labels; the ELSE branch is
optional. If the value of x does not match any case label and ELSE is
absent, the program is terminated with a run-time error.

------------------------------------------------------------------------------
        Concatenation of string and character constants

  Concatenation ("+") of constant strings and characters of type CHAR is
allowed:

  str = CHR(39) + "string" + CHR(39); (* str = "'string'" *)

  newline = 0DX + 0AX;

------------------------------------------------------------------------------
        Type test and type guard of a null pointer

  The original language report does not define the behaviour of a program
when the type guard p(T) and the type test p IS T are performed with
p = NIL. In many Oberon implementations, performing such an operation
results in a run-time error. In this implementation, the type guard of a
null pointer does not cause an error, and the type test yields the result
FALSE. In a number of cases this allows the use of the type guard to be
reduced considerably.

------------------------------------------------------------------------------
        Additional standard procedures


        COPY (x: ARRAY OF CHAR; VAR v: ARRAY OF CHAR);
                v := x;
                If LEN(v) < LEN(x), the string x is copied
                incompletely.

        LSR (x, n: INTEGER): INTEGER
                Logical shift of x right by n bits.

        MIN (a, b: INTEGER): INTEGER
                Minimum of two values.

        MAX (a, b: INTEGER): INTEGER
                Maximum of two values.

        BITS (x: INTEGER): SET
                Interprets x as a value of type SET.
                Performed at compile time.

        LENGTH (s: ARRAY OF CHAR): INTEGER
                Length of the 0X-terminated string s, not counting the
                character 0X. If the character 0X is absent, the function
                returns the length of the array s. s cannot be a constant.

------------------------------------------------------------------------------
        Importing modules with a path and file name

Examples:

    IMPORT Math IN "./lib/math.ob07"; (* relative to the current module *)

    IMPORT M1 IN "C:\lib\math.ob07"; (* absolute path *)

------------------------------------------------------------------------------
        Use of general-purpose registers R4 - R15

    R4 - R7:   register stack (intermediate values of expressions),
               volatile registers (no need to save)

    R8 - R11:  not used by the compiler, can be used in code
               procedures, non-volatile (must be saved before
               use and restored afterwards)

    R12 - R14: reserved for possible special use in
               the future

    R15:       heap pointer, used in the standard procedure NEW and
               also for stack overflow control

------------------------------------------------------------------------------
        Procedure calls and the stack frame

  The calling rules are similar to the cdecl convention (x86):
  - parameters are passed on the stack from right to left
  - the result, if any, is returned in register R4
  - the calling procedure clears the stack

  State of the stack while a procedure is executing:

  lower addresses <- |var3|var2|var1|PC|arg1|arg2|arg3| -> higher addresses

  PC   - the value of the PC register before the call (return address)
  argX - parameters in the order of declaration (left to right)
  varX - local variables in the order of use in the procedure

  The size of each item on the stack (except local variables of structural
  types) is 1 machine word (2 bytes). Structural variables (arrays and
  records) occupy space on the stack according to their size (taking
  alignment into account).

  The placement of local variables depends on their sizes and order of
  use, and is generally undefined. If a variable is not used explicitly,
  the compiler does not allocate space for it on the stack.

------------------------------------------------------------------------------
        Hidden procedure parameters

  Some procedures can have hidden parameters; they are absent from the list
of formal parameters but are taken into account by the compiler when
translating calls. This is possible in the following cases:

1.      A procedure has a formal parameter that is an open array:
                PROCEDURE Proc (x: ARRAY OF ARRAY OF REAL);
        The call is translated as follows:
                Proc(LEN(x), LEN(x[0]), SYSTEM.ADR(x))
2.      A procedure has a formal variable parameter of type RECORD:
                PROCEDURE Proc (VAR x: Rec);
        The call is translated as follows:
                Proc(SYSTEM.TYPEID(Rec), SYSTEM.ADR(x))

------------------------------------------------------------------------------
        Code procedures

  The compiler supports procedures written in machine code.
  Syntax:

  PROCEDURE "[code]" name [ (parameters): ResultType ]
      MachineWord, MachineWord,... MachineWord;

  The ";" after the header and the END "name" at the end of the procedure
  are not used.
  MachineWord - an integer constant (including a constant expression).
  For example:

  PROCEDURE [code] asr (n, x: INTEGER): INTEGER  (* ASR(x, n) -> R4 *)
      4115H, 2,              (*  MOV  2(SP), R5; R5 <- n  *)
      4114H, 4,              (*  MOV  4(SP), R4; R4 <- x  *)
      0F035H, 15,            (*  AND  #15, R5             *)
      2400H + 3,             (*  JZ   L1                  *)
                             (*  L2:                      *)
      1104H,                 (*  RRA  R4                  *)
      8315H,                 (*  SUB  #1, R5              *)
      2000H + 400H - 3;      (*  JNZ  L2                  *)
                             (*  L1:                      *)

  The compiler automatically appends the RET instruction to such a procedure.
  The way parameters and the result are passed does not change.

  Code procedures can also be used to add constant data to a program:

  PROCEDURE [code] sqr
      0, 1, 4, 9, 16, 25, 36, 49, 64, 81;

  To obtain the address of such a "procedure": SYSTEM.ADR(sqr).
  To obtain the address of the n-th machine word: SYSTEM.ADR(sqr) + n * 2.

  To use code procedures, the SYSTEM pseudo-module must be imported.

------------------------------------------------------------------------------
        Interrupt handling

  When an interrupt request occurs, the processor:
  - pushes the value of the PC register onto the stack
  - pushes the value of the SR register onto the stack
  - clears the SR register
  - jumps to the address IV[priority], where
    IV - the interrupt vector table,
    priority - the interrupt priority (the index of the entry in the IV table) (0..30)

  The compiler generates interrupt handling code:

                   ; IV[0] = address of the next instruction
  PUSH  #0         ; push the interrupt priority onto the stack
  JMP   Label      ; jump to the handler

                   ; IV[1] = address of the next instruction
  PUSH  #1         ; push the interrupt priority onto the stack
  JMP   Label      ; jump to the handler

  ...
                   ; IV[priority] = address of the next instruction
  PUSH  #priority  ; push the interrupt priority onto the stack
  JMP   Label      ; jump to the handler

  ...
                   ; IV[30] = address of the next instruction
  PUSH  #30        ; push the interrupt priority onto the stack

  Label:
  PUSH  R4         ; save the working registers (R4 - R7)
  ...
  PUSH  R7
  MOV   SP, R4     ; set R4 to the interrupt data structure (see below)
  ADD   #8, R4
  PUSH  R4         ; pass the interrupt parameter to the handler (see below)
  PUSH  @R4        ; pass the priority parameter to the handler (see below)
  CALL  int        ; call the handler (see below)
  ADD   #4, SP     ; remove the handler parameters from the stack
  POP   R7         ; restore the working registers (R7 - R4)
  ...
  POP   R4
  ADD   #2, SP     ; remove the priority value from the stack
  RETI             ; return from the interrupt (restore SR and PC)

------------------------------------------------------------------------------
        Error handling

  If an error occurs while the program is running, a common error handler
is called, which:

  - disables interrupts
  - resets the stack (to avoid overflow while the error is being handled)
  - passes parameters to the user handler (see below)
  - calls the user handler (if one is assigned)
  - disables interrupts again
  - turns off the CPU and all clock signals

  If the CPU does not need to be turned off, the user handler can, for
example, restart the program.

Error codes:

 1       ASSERT(x), when x = FALSE
 2       dereferencing of a null pointer
 3       integer division by a non-positive number
 4       call of a procedure through a procedure variable with a null value
 5       type guard error
 6       array bounds violation
 7       unhandled expression value in a CASE statement
 8       error copying arrays v := x, if LEN(v) < LEN(x)
 9       CHR(x), if (x < 0) OR (x > 255)
10       stack overflow
11       implicit conversion of x:INTEGER to v:BYTE, if (x < 0) OR (x > 255)

------------------------------------------------------------------------------
        Program initialization and finalization

  At the beginning of the program the compiler inserts code that:
  - initializes the SP and R15 registers
  - turns off the watchdog timer
  - assigns an empty interrupt handler and an empty error handler

  At the end of the program it adds the instruction
  BIS #16, SR; turn off the CPU

------------------------------------------------------------------------------
        RAM structure

  start -> | heap/stack | special variables | global variables | <- end

  The compiler supports a RAM size of 128..2048 bytes. The user global
variables and hidden special variables are located at the higher addresses.
The remaining part of the memory is set aside for the heap and the stack
(at least 40 bytes, the minimum needed for interrupt and error handling).
When the program starts, the address of the beginning of the heap/stack
area is written to register R15, and register SP is set to the end of this
area (the address of the special variables). When memory is allocated by
the NEW procedure, the value of register R15 is increased (if there is free
memory). Thus the stack and the heap grow towards each other.

Stack overflow checking is performed only on entry to a procedure, if this
check is not disabled at compile time (-nochk s).
Stack checking is not performed:
  - while a procedure is executing
  - on entry to a code procedure
  - while the module body is executing

------------------------------------------------------------------------------
        ROM structure

  start -> | free area | code | data | interrupt vectors | <- end

  The compiler supports a ROM size of 2048..24576 bytes. The interrupt
vector table (64 bytes) is located at the higher addresses, at addresses
0FFC0H..0FFFFH. Immediately before it are the data (the type table, strings,
sets), and before the data is the program code. The start address of the
code coincides with the entry point of the program (the reset vector). If
the ROM size is larger than the size of the program, a free area remains in
front of the code.

MODULE MSP430

CONST

    SR register bits:

    GIE     = {3}
    CPUOFF  = {4}
    OSCOFF  = {5}
    SCG0    = {6}
    SCG1    = {7}


TYPE

    TInterrupt = RECORD priority: INTEGER; sr: SET; pc: INTEGER END
        interrupt data structure

        priority - interrupt priority:

        address  priority
        0FFFEH     31
        0FFFCH     30
        0FFFAH     29
        ...
        0FFC0H      0

        sr - saved value of the SR register
        pc - saved value of the PC register


    TTrapProc = PROCEDURE (modNum, modName, err, line: INTEGER);
        Error handler procedure.

        modNum  - module number (in the compilation report:
                  compiling (modNum) "modName" )
        modName - address of the module name
        err     - error number
        line    - line number


    TIntProc = PROCEDURE (priority: INTEGER; interrupt: TInterrupt)
        Interrupt handler procedure.

        priority  - interrupt priority
        interrupt - interrupt data structure


    PROCEDURE SetTrapProc (TrapProc: TTrapProc)
        Assign the error handler.


    PROCEDURE SetIntProc (IntProc: TIntProc)
        Assign the interrupt handler.


    PROCEDURE Restart
        Restart the program.
        In doing so: the SR register is cleared, the program initialization
        code is executed again (see above). All other state of the RAM and of
        the device registers is preserved.


    PROCEDURE SetIntPC (interrupt: TInterrupt; NewPC: INTEGER)
        interrupt.pc := NewPC
        After returning from the interrupt, the PC register will receive the
        value NewPC.


    PROCEDURE SetIntSR (interrupt: TInterrupt; NewSR: SET)
        interrupt.sr := NewSR
        After returning from the interrupt, the SR register will receive the
        value NewSR.


    PROCEDURE DInt
        Disable interrupts.


    PROCEDURE EInt
        Enable interrupts.


    PROCEDURE CpuOff
        Turn off the CPU (set the CPUOFF bit of the SR register).


    PROCEDURE Halt
        Disable interrupts, turn off the CPU and all clock signals.


    PROCEDURE SetSR (bits: SET)
        Set the bits specified in bits of the SR register.


    PROCEDURE ClrSR (bits: SET)
        Clear the bits specified in bits of the SR register.


    PROCEDURE Delay (n: INTEGER)
        Delay program execution by 1000*n clock cycles,
        but not less than 2000 clock cycles.
