        Oberon-07/16 programming language compiler for x86_64
                Windows/Linux
------------------------------------------------------------------------------

        Command line options

  Input - text files of modules with the ".ob07" extension, ANSI or UTF-8
encoding with a BOM signature.
  Output - an executable file in the PE32+ or ELF64 format.
  Parameters:
  1) the name of the main module
  2) the application type
      "win64con" - Windows64 console
      "win64gui" - Windows64 GUI
      "win64dll" - Windows64 DLL
      "linux64exe" - Linux ELF64-EXEC
      "linux64so" - Linux ELF64-SO

  3) optional options
      -out <file_name> the name of the resulting file; by default it matches
          the name of the main module, but with a different extension
          (corresponding to the executable file type)
      -stk <size> stack size in megabytes (2 MB by default,
          allowed range is 1 to 32 MB)
      -tab <width> tab size (used to compute coordinates in the
          source text), 4 by default
      -nochk <"ptibcwra"> disable run-time checks
      -lower allow keywords and built-in identifiers in
          lower case (default)
      -upper upper case only for keywords and built-in
          identifiers
      -def <name> define a conditional compilation symbol
      -uses output the list of imported modules
      -fa <size> alignment of the sections of a PE32 file in bytes, possible
          values: 512, 1024, 2048, 4096. 512 by default

      the -nochk option is given as a string of characters:
      "p" - pointers
      "t" - types
      "i" - indexes
      "b" - implicit conversion of INTEGER to BYTE
      "c" - range of the argument of the CHR function
      "w" - range of the argument of the WCHR function
      "r" - equivalent to "bcw"
      "a" - all checks

      The order of the characters is arbitrary. The presence of a given
      character in the string disables the corresponding check.

      For example: -nochk it - disable the index check and the type guard.
      -nochk a - disable all checks that can be disabled.

  For example:

  Compiler.exe "C:\example.ob07" win64con -out "C:\example.exe" -stk 1
  Compiler.exe "C:\example.ob07" win64dll -out "C:\example.dll" -nochk pti
  Compiler "source/Compiler.ob07" linux64exe -out "source/Compiler" -nochk a

  On successful compilation the compiler returns exit code 0, otherwise 1.

------------------------------------------------------------------------------
        Differences from the original

1.      The pseudo-module SYSTEM is extended
2.      The character "_" is allowed in identifiers
3.      System flags are added
4.      The CASE statement is improved (constant expressions in the case
        labels and an optional ELSE branch are added)
5.      The set of standard procedures is extended
6.      The semantics of the type guard/type test is refined for a NIL pointer
7.      Single-line comments are added (they start with the character pair "//")
8.      Inheritance from a pointer type is allowed
9.      Syntax for importing procedures from external libraries is added
10.     "Strings" can also be enclosed in single quotes: 'string'
11.     The type WCHAR is added
12.     Concatenation of string and character constants is added
13.     Modules can be imported with a path and a file name specified
14.     Special syntax for conditional compilation is added (see CC.txt)
15.     The procedure name at the end of the declaration (after END) is optional
16.     Lower case is allowed for keywords

------------------------------------------------------------------------------
        Implementation notes

1.      Basic types

          Type             Range of values                       Size, bytes

        INTEGER       -9223372036854775808 .. 9223372036854775807       8
        REAL          4.94E-324 .. 1.70E+308                            8
        CHAR          ASCII character (0X .. 0FFX)                      1
        BOOLEAN       FALSE, TRUE                                       1
        SET           set of integers {0 .. 63}                         8
        BYTE          0 .. 255                                          1
        WCHAR         Unicode character (0X .. 0FFFFX)                  2

2.      Maximum length of identifiers is 255 characters
3.      Maximum length of string constants is 511 characters (UTF-8)
4.      Maximum number of dimensions of open arrays is 5
5.      The procedure NEW fills the allocated block of memory with zeros
6.      Global and local variables are initialized to zero
7.      Unlike many Oberon implementations, there is no garbage collector and
        no dynamic module loading
8.      In expressions the type BYTE is always converted to INTEGER
9.      No overflow checking of expression values is performed
10.     Run-time errors:

 1       ASSERT(x), when x = FALSE
 2       dereference of a NIL pointer
 3       integer division by a non-positive number
 4       call of a procedure through a procedure variable with a NIL value
 5       type guard error
 6       array bounds violation
 7       value of an expression in a CASE statement that is not handled
 8       error on array copy v := x, if LEN(v) < LEN(x)
 9       CHR(x), if (x < 0) OR (x > 255)
10       WCHR(x), if (x < 0) OR (x > 65535)
11       implicit conversion of x:INTEGER to v:BYTE, if (x < 0) OR (x > 255)

------------------------------------------------------------------------------
        The pseudo-module SYSTEM

  The pseudo-module SYSTEM contains low-level and unsafe procedures; errors in
the use of the procedures of the pseudo-module SYSTEM can lead to corruption of
run-time data and abnormal termination of the program.

        PROCEDURE ADR(v: any type): INTEGER
                v - a variable or a procedure;
                returns the address of v

        PROCEDURE SADR(x: string constant (CHAR UTF-8)): INTEGER
                returns the address of x

        PROCEDURE WSADR(x: string constant (WCHAR)): INTEGER
                returns the address of x

        PROCEDURE VAL(T; v: any type): T
                v - a variable;
                interprets v as a variable of type T

        PROCEDURE SIZE(T): INTEGER
                returns the size of type T

        PROCEDURE TYPEID(T): INTEGER
                T - a record type or a pointer type,
                returns the type number in the table of record types

        PROCEDURE INF(): REAL
                returns the special real value "infinity"

        PROCEDURE MOVE(Source, Dest, n: INTEGER)
                Copies n bytes of memory from Source to Dest,
                the regions Source and Dest must not overlap

        PROCEDURE GET(a: INTEGER;
                VAR v: any basic type, PROCEDURE, POINTER)
                v := Memory[a]

        PROCEDURE GET8(a: INTEGER;
                       VAR x: INTEGER, SET, BYTE, CHAR, WCHAR, SYSTEM.CARD32)
                Equivalent to
                SYSTEM.MOVE(a, SYSTEM.ADR(x), 1)

        PROCEDURE GET16(a: INTEGER;
                        VAR x: INTEGER, SET, WCHAR, SYSTEM.CARD32)
                Equivalent to
                SYSTEM.MOVE(a, SYSTEM.ADR(x), 2)

        PROCEDURE GET32(a: INTEGER; VAR x: INTEGER, SET, SYSTEM.CARD32)
                Equivalent to
                SYSTEM.MOVE(a, SYSTEM.ADR(x), 4)

        PROCEDURE PUT(a: INTEGER; x: any basic type, PROCEDURE, POINTER)
                Memory[a] := x;
                If x: BYTE or x: WCHAR, the value of x will be extended to
                64 bits; to store bytes use SYSTEM.PUT8, for WCHAR --
                SYSTEM.PUT16

        PROCEDURE PUT8(a: INTEGER;
                       x: INTEGER, SET, BYTE, CHAR, WCHAR, SYSTEM.CARD32)
                Memory[a] := the low 8 bits of (x)

        PROCEDURE PUT16(a: INTEGER;
                        x: INTEGER, SET, BYTE, CHAR, WCHAR, SYSTEM.CARD32)
                Memory[a] := the low 16 bits of (x)

        PROCEDURE PUT32(a: INTEGER;
                        x: INTEGER, SET, BYTE, CHAR, WCHAR, SYSTEM.CARD32)
                Memory[a] := the low 32 bits of (x)

        PROCEDURE COPY(VAR Source: any type; VAR Dest: any type; n: INTEGER)
                Copies n bytes of memory from Source to Dest.
                Equivalent to
                SYSTEM.MOVE(SYSTEM.ADR(Source), SYSTEM.ADR(Dest), n)

        PROCEDURE CODE(byte1, byte2,... : BYTE)
                Insertion of machine code,
                byte1, byte2 ... - constants in the range 0..255,
                for example:

                SYSTEM.CODE(048H,08BH,045H,010H) (* mov rax,qword[rbp+16] *)

  Also, the type CARD32 (4 bytes) is defined in the module SYSTEM. No explicit
operations are allowed for the type CARD32, with the exception of assignment.

  The functions of the pseudo-module SYSTEM cannot be used in constant
expressions.

------------------------------------------------------------------------------
        System flags

  In the declaration of procedure types and global procedures, a calling
convention flag may be specified after the keyword PROCEDURE:
[win64], [systemv], [windows], [linux], [oberon], [ccall].
For example:

        PROCEDURE [win64] MyProc (x, y, z: INTEGER): INTEGER;

  The flag [windows] is a synonym for [win64], [linux] is a synonym for
[systemv]. The flag [ccall] is a synonym for [win64] or [systemv] (depending on
the target OS). The "-" sign after the flag name ([win64-], [linux-], ...) means
that the result of the procedure may be ignored (not allowed for the type REAL).
If no flag is specified, or the flag [oberon] is specified, the internal calling
convention is used. [win64] and [systemv] are used for interfacing with the
operating system and external applications.

  In the declaration of record types, the flag [noalign] may be specified after
the keyword RECORD. The flag [noalign] means that the fields of the record are
not aligned. Records with a system flag cannot have a base type and cannot be
base types for other records.
  To use system flags, SYSTEM must be imported.

------------------------------------------------------------------------------
        The CASE statement

  Syntax of the CASE statement:

        CaseStatement =
                CASE Expression OF Case {"|" Case}
                        [ELSE StatementSequence] END.
        Case = [CaseLabelList ":" StatementSequence].
        CaseLabelList = CaseLabels {"," CaseLabels}.
        CaseLabels = ConstExpression [".." ConstExpression].

  For example:

        CASE x OF
        |-1:    DoSomething1
        | 1:    DoSomething2
        | 0:    DoSomething3
        ELSE
                DoSomething4
        END

  Constant expressions can be used in the case labels; the ELSE branch is
optional. If the value of x does not match any variant and there is no ELSE,
the program is terminated with a run-time error.

------------------------------------------------------------------------------
        The type WCHAR

  The type WCHAR is added to the language for convenient Unicode support. For
the types WCHAR and ARRAY OF WCHAR all the same operations are allowed as for
the types CHAR and ARRAY OF CHAR, with the exception of the built-in procedure
CHR, which returns only the type CHAR. To obtain a value of type WCHAR, the
procedure WCHR should be used instead of CHR. For correct handling of the type,
the source text must be saved in UTF-8 encoding with BOM.

------------------------------------------------------------------------------
        Concatenation of string and character constants

  Concatenation ("+") of constant strings and characters of type CHAR is
allowed:

  str = CHR(39) + "string" + CHR(39); (* str = "'string'" *)

  newline = 0DX + 0AX;

------------------------------------------------------------------------------
        Type test and type guard for a NIL pointer

  The original language report does not define the behaviour of a program when
the type guard p(T) or the type test p IS T is performed with p = NIL. In many
Oberon implementations, performing such an operation leads to a run-time error.
In this implementation the type guard of a NIL pointer does not lead to an
error, and the type test yields FALSE. In a number of cases this allows the
frequency of use of the type guard to be considerably reduced.

------------------------------------------------------------------------------
        Additional standard procedures

        DISPOSE (VAR v: any_pointer)
                Frees the memory allocated by the procedure NEW for the
                dynamic variable v^, and assigns the value NIL to the
                variable v.

        COPY (x: ARRAY OF CHAR/WCHAR; VAR v: ARRAY OF CHAR/WCHAR);
                v := x;
                If LEN(v) < LEN(x), the string x will be copied only
                partially

        LSR (x, n: INTEGER): INTEGER
                Logical shift of x by n bits to the right.

        MIN (a, b: INTEGER): INTEGER
                The minimum of two values.

        MAX (a, b: INTEGER): INTEGER
                The maximum of two values.

        BITS (x: INTEGER): SET
                Interprets x as a value of type SET.
                Performed at compile time.

        LENGTH (s: ARRAY OF CHAR/WCHAR): INTEGER
                The length of the 0X-terminated string s, not counting the
                character 0X. If the character 0X is absent, the function
                returns the length of the array s. s cannot be a constant.

        WCHR (n: INTEGER): WCHAR
                Type conversion, analogous to CHR(n: INTEGER): CHAR

------------------------------------------------------------------------------
        Import of modules with a path and a file name specified

Examples:

    IMPORT Math IN "./lib/math.ob07"; (* relative to the current module *)

    IMPORT M1 IN "C:\lib\math.ob07"; (* absolute path *)

------------------------------------------------------------------------------
        Imported procedures

  Import syntax:

  PROCEDURE [callconv, library, function] proc_name (FormalParam): Type;

  - callconv -- calling convention
  - library -- the file name of the dynamic library (string constant)
  - function -- the name of the imported procedure (string constant); if an
  empty string is specified, the procedure name = proc_name

  for example:

  PROCEDURE [windows, "kernel32.dll", "ExitProcess"] exit (code: INTEGER);

  PROCEDURE [windows, "kernel32.dll", ""] GetTickCount (): INTEGER;

  At the end of the declaration "END proc_name;" may be added (optionally)

  Declarations of imported procedures must be located in the global scope of
  the module after the variable declarations, together with the declarations of
  "ordinary" procedures, from which imported ones differ only in the absence of
  a procedure body. In all other respects the same rules apply to such
  procedures: they can be called, assigned to a procedure variable, or their
  address can be taken.

  Since an imported procedure always has an explicit calling convention, a
  compatible procedure type must also be declared with the calling convention
  specified:

  VAR
      ExitProcess: PROCEDURE [windows] (code: INTEGER);

  For Linux, imported procedures are not implemented.

------------------------------------------------------------------------------
        Hidden procedure parameters

  Some procedures may have hidden parameters; they are absent from the list of
formal parameters, but are taken into account by the compiler when translating
calls. This is possible in the following cases:

1.      The procedure has a formal parameter that is an open array:
                PROCEDURE Proc (x: ARRAY OF ARRAY OF REAL);
        The call is translated as follows:
                Proc(LEN(x), LEN(x[0]), SYSTEM.ADR(x))
2.      The procedure has a formal variable parameter of type RECORD:
                PROCEDURE Proc (VAR x: Rec);
        The call is translated as follows:
                Proc(SYSTEM.TYPEID(Rec), SYSTEM.ADR(x))

  Hidden parameters must be taken into account when interfacing with external
applications.

------------------------------------------------------------------------------
        The RTL module

  All programs implicitly use the RTL module. The compiler translates some
operations (type test and type guard, string comparison, run-time error
messages, etc.) as calls to procedures of this module. These procedures should
not be called explicitly.
  Run-time error messages are output in dialog boxes (Windows), or to the
terminal (Linux).

------------------------------------------------------------------------------
        The API module

  There are several implementations of the API module (for different OSes).
  Like the RTL module, the API module is not intended for direct use.
It provides the interface between RTL and the OS.

------------------------------------------------------------------------------
        Generation of DLL executable files

  Only procedures may be exported. For this, the procedure must be located in
the main module of the program, its name must be marked with the export symbol
("*"), and a calling convention must be specified. Procedures that are imported
from other dll libraries cannot be exported.
